## Findings considered and rejected

From the 2026-08-08 run:

- Weekly/monthly/yearly range selection: deferred because only the monthly question is currently
  grounded in the product request and complete enough in the ledger model.
- Historical SMS backfill: deferred because it changes onboarding workload, privacy expectations,
  and data coverage rather than only report presentation.
- A separate cash-flow root tab: rejected because Reports is already a root and nested report modes
  solve the hierarchy without expanding the five-item navigation bar.
- Copying the reference app's purple/gold palette: rejected because this app already has a coherent
  theme and semantic color roles; only the monthly comparison pattern is relevant.

From the 2026-09-10 audit (vetted against the code; do not re-report):

- "PWA pairing is broken — `/v1/pair` requires a device token": wrong; the all-zero placeholder
  secret passes `splitToken`'s syntactic gate deliberately, and the Durable Object's `pair`
  authorises by one-time code (`sync/src/index.ts:394`), covered by `sync/test/sync.test.ts`.
- "Scope key persists in browser history": already mitigated — `takePairing` in `pwa/src/main.tsx`
  strips the fragment via `history.replaceState`; the residual (screenshot of the QR itself) is a
  documented ceiling in `pwa/src/crypto.ts`.
- `!!` clusters at money/persistence boundaries (in `Derived.kt`, `Links.kt`,
  `Ledger.kt`, `AppVm.kt` — formerly `MainActivity.kt` — and `Daily.kt`): every cited site is locally guarded
  (groupBy non-empty, emptiness `continue`, `clockRunsAhead` null-checks, wallet-filtered lists);
  13 occurrences in 29k lines is discipline, not debt.
- `allBalances` N+1 (`Derived.kt`): real shape, but N is a household's handful of accounts on
  local SQLite — measured impact too small to justify fix risk.
- PWA `decisionsFor` per-target reads (`pwa/src/db.ts`): all `getAll`s share one IndexedDB
  transaction on an indexed key; not worth restructuring.
- `buildCashFlow` multi-pass over entries (`Reports.kt`): sits behind `remember(...)` keyed on
  its inputs (the report screen's caller in `Ui.kt`), recomputes only on state change; in-memory passes over a year's
  entries are single-digit ms — not worth the risk on money-display code. Revisit only with a
  measured jank trace.
- Dependency lag: none found — catalogs current, Dependabot queue is routine bumps gated by CI.
- TS formatter/linter adoption: optional churn; the three packages are hand-formatted
  consistently. AGENTS.md (plan 007) records the convention instead.

From the 2026-11-13 UI/UX and cleanup audit (fixed directly rather than planned; do not re-report):

- Off-scale 2dp/6dp/10dp spacing nudges (both platforms): optical adjustments, not drift.
- `barTint`'s hard-coded colours in `Report.kt`: DESIGN.md names it the report's own palette.
- PWA twins for Android's TalkBack `onClickLabel`s: VoiceOver has no dependable counterpart and
  the PWA's buttons already carry accessible names.
- Splitting the body of the `AppVm` class: its domain blocks reach into private state, so it is
  not a whole-declaration move; only `UiState` is cleanly movable.
- Web Push for the PWA's closed-app notifications: needs a push service and a subscription
  endpoint per device, which is an identifier — against PRODUCT.md's non-negotiables.
- `apple-mobile-web-app-status-bar-style` `black-translucent` possibly drawing white status-bar
  text on the light theme: unverified without an iPhone; left as is until checked on a device.

From the 2026-11-20 full audit (vetted against the code; do not re-report):

- In-memory, per-isolate rate limiters on the rates Worker (`/wallet-balance`, `/feedback`,
  `/crash`), and the PWA's requests sharing one bucket behind the sync Worker's proxy: both are
  ceilings the code names itself (`worker/src/checks.ts` `TokenBucket`, `worker/src/index.ts`
  near `feedbackLimiter`), with the upgrade written beside them — pass the client's address
  through an authenticated header. A per-address limiter at the sync edge alone would not lift
  the shared bucket, so nothing was planned.
- Tombstones never compacted in the sync Durable Object: named ceiling with its upgrade path
  (`sync/src/index.ts` near `MAX_STORED_ROWS`).
- Replacing SMS-derived sync record ids (a SHA-256 of the message) with a keyed hash: a
  sync-format migration — new ids, tombstones for the old, a `SYNC_READ_VERSION` bump, both
  clients — for an exposure that needs the server's data plus the message text. Plan 022 makes
  the README say what the id is instead.
- Migrating the `Double`-Toman bank balance (`BankAccount.balance`) to `Long` Rial: hand-anchored
  figures no rescan can rebuild; AGENTS.md now records the exception (plan 022).
- Pinning `loadSession` to the configured origin: about thirty callers and five test suites that
  save local-server sessions; stripping the session on restore (plan 012) closes the only
  unguarded way one is written.
- A length cap on SMS bodies before parsing: would change parser output on long concatenated
  messages; the two quadratic regexes are fixed instead (plan 013).
- A gzip fallback for backups on Safari below 16.4: needs an inflate dependency; plan 013 makes
  the backup page say so in words there.
- Key and device token in plain `durable_meta` rather than Android Keystore: the app sandbox and
  disabled Auto Backup cover the realistic cases; Keystore wrapping adds OEM failure modes.
- Shape validation of every restored PWA row: low likelihood (a crafted file plus its
  passphrase), and plan 017's error screen removes the blank-page consequence.
- A tombstone-sweep race in `Sync.kt` (snapshot read before `needsDerive`) and re-reads past the
  2,000-key `seenSms` window: low-confidence, narrow preconditions; investigate only if a
  report matches.
- PWA code-splitting: one 568 KB chunk plus lazy jsQR, all precached; not worth the complexity.
